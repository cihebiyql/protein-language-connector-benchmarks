# node1 独立收尾与 GitHub 发布

本轮45组实验的收尾程序已迁到 node1：等待既有训练队列终态，逐组独立复算，保留全部成功、失败及缺失位置，再从节点直接发布到本仓库。本机关机、断网或关闭对话不会停止节点上的这些步骤。

这是本轮任务的一次性后台进程，完成后退出，没有创建 cron、系统服务或应用定时监控。原训练主进程、冻结源码、数据划分、评价标准和已有结果保持原样；旧的本机收尾进程在节点接管验证通过后退休，其日志和产物保留。

## 执行链路

1. `resources/launch_node1_publish.py` 从节点私有配置启动独立会话，标准输入关闭，日志写到节点文件。
2. `resources/node1_publish.py` 使用原有 `finish_and_export.py` 等待队列结束，重新核验45个位置及冻结指纹，并生成原始导出包。
3. 核验导出包及逐文件SHA，复用既有发布过滤规则：ELM逐查询材料、候选向量及权重仍保留私有；允许公开的数据和科学预测保持原字节，行政元数据另作规范化并记录双SHA。
4. 使用专用仓库副本和隔离工作目录提交结果、分析及 `COMPLETION_STATUS.json`。只追加提交，不强制推送；并发更新仅在本次工作目录合并。网络错误作有界重试，失败记录保留。
5. 推送后核对远端提交，并通过匿名下载校验公开文件，写入节点本地发布回执。

结果发布命名空间为 `formal_v1_node1_terminal_v1`。均值和标准差仍要求同配置的三个固定种子完整有效，缺失结果不以历史实验替代。早期分数不会改变队列、训练预算或评价标准。

## 运行环境和权限

Git以Ubuntu发行包解包到本任务的私有目录，使用进程级环境变量，不修改共享训练环境。GitHub认证使用节点新生成、仅登记到本仓库的部署密钥；个人Token和个人SSH私钥未复制到节点。密钥、配置、原始进程信息和日志均不公开。

汇总进程禁用CUDA，四个CPU计算库各固定2线程，不增加GPU任务。配置只允许覆盖Git所需的PATH、GIT_EXEC_PATH和GIT_TEMPLATE_DIR。

## 后续维护

节点私有配置指定本轮scope、队列、解释器、专用仓库、结果命名空间和部署密钥命令。正常情况下无需人工续跑。发现已有活进程时，启动器拒绝重复启动；遇到旧的失败记录时保留现场，不自动重置或重训。恢复操作应先核对节点私有回执、源码与配置指纹。
